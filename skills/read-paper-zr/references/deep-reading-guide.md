# 深度讲解与验收指南

用于默认笔记的“2.论文精读”，或定位“有结论但没讲明白”的单点追问。前面的“1.论文简读”负责简洁概括，本指南要求的机制与证据解释要实际保留在精读中。目标是补齐理解，不是堆字数、逐行翻译、展开所有附录或写审稿意见。

## 1. 阅读要留下什么理解

围绕当前论文维护简明理解记录；复杂批量任务可保存到工作区：

| 需要重建的内容 | 回到哪里确认 | 最终应写进正文的解释 |
| --- | --- | --- |
| 问题与最近已有做法 | 引言、问题定义、相关工作 | 旧做法哪一步不满足需求 |
| 核心计算与信息流 | 方法、公式、算法、方法图 | 关键量的来源、运算、去向与作用 |
| 训练/建库与运行 | 实现、算法、相关附录 | 标签/反馈何时可得、谁更新、在线执行什么 |
| 关键主张与证据 | 主表、消融、分析图、协议 | 对照怎样区分解释、观察支持到哪一步 |
| 不确定处 | 冲突段落、附录或必要的一手代码 | 原文明确什么、缺什么、影响何处 |

这不是固定交付表，也无需把工具读取日志写给用户。重要的是将获得的理解展开成正文；事后只保留一句概述会丢失阅读成果。

## 2. 从模块名到可执行机制

面对核心模块，追问以下问题，答案应在相邻正文连起来：

- 输入是原始数据、编码表示、历史统计，还是另一模块预测？当前阶段实际可得吗？
- 在什么对象上运算：样本、token、模型、类别、边还是时间步？集合、索引、形状和共享关系决定理解时需要明确。
- 具体怎样得到输出？归一化沿哪个轴、对哪组元素求和？先平均再加权与先加权再平均是否相同？分数大小意味着什么？
- 输出怎样进入后续决策、损失或反馈？它是估计、代理标签、分布参数还是真值？
- 操作回应哪个困难，简单替代失去什么？回答来自证据还是机制分析？

“编码器提取特征”“利用历史得到分数”“强化学习优化”留下了整个核心步骤，需要继续下钻；普通基础组件每层矩阵不影响理解时则不必展开。

涉及学习或采样时注意：

- 监督样本如何组成，正负例/偏好/奖励如何得到，目标与预测维度是否对应。
- 损失各项约束哪些模块，哪些参数接收训练信号，冻结对象如何参与前向计算。
- 推理实际读取哪些量，有没有离线可见而在线不可见的信息；建库、重训、检索更新不能混淆。
- 随机策略的分布假设、参数估计和采样对象是什么；区分参数后验、不确定性与观测噪声，不只报算法名。
- 循环如何开始、终止与更新；回退、空集合和新对象等核心分支以原文为准，缺失就注明。

需要背景时补直接服务当前操作的小解释，不插入整章通用教程。

## 3. 公式与完整例子

先说明公式完成什么操作，再写公式和变量。把承载设计的公式连成计算链，说明上一步输出在哪里代入；关键中间步骤不能省成“可得”。补充推导与原式分开，不能替作者添加假设。

例子首先要贴近日常生活，让没有技术背景的读者也能跟上，再将各角色、操作和结果映射回本文方法。决定性权重或分数需要演示时，给可核算的输入、中间值与输出；不将整份日常例子变成算术练习。以下只示范技术解释的深度，**全部数值为教学构造，不是论文结果，也不能套用到其他方法**。

浅写法：“识别任务，再对各模型任务表现加权，选择质量—成本最优模型。”

较完整的解释：

1. 对一个问题，识别器预测两类任务概率 $l=(0.75,0.25)$；这是暂定已算出的模型输出，不是真实标签。
2. A、B两模型在两任务上的预测质量分别为 $(0.90,0.40)$、$(0.70,0.80)$；归一化预测成本分别为 $(0.50,0.70)$、$(0.20,0.30)$。它们来自离线训练的指标头，当前还没调用A、B作答。
3. 按同一任务概率边缘化：$\hat r_A=0.75\times0.90+0.25\times0.40=0.775$，$\hat c_A=0.55$；B得到 $\hat r_B=0.725$、$\hat c_B=0.225$。
4. 平衡效用 $u=0.5\hat r-0.5\hat c$ 得 $u_A=0.1125$、$u_B=0.25$，只执行B。质量权重改为0.9、成本0.1，则A为0.6425、B为0.63，改选A。
5. 解释：任务分布混合的是任务条件预测，不是模型真实答案；改变权重是在改变预测质量与费用偏好，不能把预测值当本题真实正确率。任务概率分错时，后面算术正确也可能选错模型。

这还不能替代训练解释：仍需说明任务概率怎样由输入产生、指标头的监督、哪些损失更新哪些参数。若重点是层级建库或反馈循环，也要给那个过程的具体例子，不能只在最终argmax算一道题。

理论用小实例检验定义与假设、走过证明关键跳步；系统/基准追踪请求或数据记录到最终评测。不适合数值演算时，不为“有算例”生造数字。

## 4. 实验要能区分解释

每项关键实验围绕问题，按“为什么需要 → 怎样控制比较 → 观察到什么 → 能说明什么”叙述，与方法设计对应。

例如，删检索模块后下降，不能直接证明“新相似度有效”：删除可能同时影响历史信息、回退和计算。应说明实际改变及本文证据支持的结论；更强归因缺对照时指出，但不补造实验。

主实验讲最有判别力的参照、收益分布与质量/效率取舍；消融讲被改操作及设计理由；分析图讲横纵轴、控制变量、趋势和转折。不必覆盖每张次要图，核心主张依赖的图不能只写“见图X”。

表格负责保留数字，正文负责解释模式。数据规模、超参数、节省率和勘误不能代替解释；也不能只谈趋势而省去决定判断的原始数值和条件。

## 5. 按论文类型调整

| 类型 | 深入讲解主体 | 常见的浅读替代品 |
| --- | --- | --- |
| 方法 | 关键运算、训练/运行、完整例子、设计证据 | 模块名加最终选择公式 |
| 理论 | 定义、假设、结论、证明关键步骤、边界 | 只抄定理称“有理论保证” |
| 系统 | 状态/接口、请求与资源流、调度/反馈、测量协议 | 架构框图加总加速比 |
| 数据/基准 | 构建、过滤、标注、划分、样本单位、评测器、诊断 | 数据量与排行榜 |
| 综述/观点 | 选材口径、分类依据、代表机制、联系与分歧 | 目录翻译与名称清单 |

## 6. 主动提问与解惑

报告的2.9为固定交付章节，由模型主动发现本篇论文最值得问的问题，并作实质回答。可从设计理由、容易混淆的概念、信息来源、局部交互与全局结构、训练与运行、公式或监督的作用、证据与失效条件中选择；不要机械凑类别或固定数量。

每题先直接回答，再解释原因或机制，必要时补一个通俗例子。答案要解决实际理解障碍，不用换句话复述问题或长段重复前文。原文没有交代的先回查，再区分已知事实、阅读推理与尚待验证；不能补造作者的答案，也不能把所有问题都变成否定论文的审稿意见。

本节是主动教学与解惑，不是等用户作答的测验，不用作者、年份等记忆题，不给形式评分。出处按排版说明集中整理，不恢复逐段章节尾注。

## 7. 交付前用正文回答

不看原文，仅凭正文尝试回答：

- 哪一步不同于最近做法，为什么这一步必要？
- 能否写核心算法/论证骨架，而没有“某模块神奇地产生结果”的空洞步骤？
- 核心量从哪里来、在哪个集合/轴上计算、何时可见、怎样影响下一步？训练与运行能否区分？
- 例子每个关键中间量能否算出，输出是否符合原文决策规则？
- 每项主要贡献有哪些实验或证明；消融区分了什么、还不能区分什么？
- 原文已给的关键内容是否被“未报告”“实现略”或一个缩写遮住？不确定处是否真的回查过？

核心问题答不上来就定位缺口、回读并补写。不要给形式分数、固定字数线或自动“全通过”声明；长度、目录、图片与链接检查只能验证交付完整性，不能验证科学理解。
